미니PC 물리 서버로 게임 서버 운영하기

집에 둔 미니PC 한 대에 북메이트 웹 서비스와 Java 기반 마인크래프트 서버(8GB 힙)를 함께 올려, 친구 2~3명과 24시간 쓰고 있습니다. 클라우드 없이 물리 서버를 직접 운영하면서 보안, 성능, 접속, 리포트를 하나씩 갖춰 나갔습니다.

보안 조치
  • 서버에 들어온 로그를 직접 점검했습니다. 침입에 성공한 흔적은 없었고, .env, .git, *.php 같은 경로를 노리는 웹 스캐닝 1,300여 건이 모두 404·403으로 막힌 것을 확인했습니다.
  • SSH는 키 인증만 허용하고 기본 포트가 아닌 포트로 옮겼습니다. 로그인 실패가 반복되는 IP는 fail2ban으로 차단합니다.
  • 웹 스캐너 차단 규칙(fail2ban)을 직접 만들었습니다. 모든 요청이 Spring으로 넘어가 nginx 오류 로그에 404가 남지 않아서, 기본 규칙 대신 접근 로그에서 스캐너 경로를 10분에 3번 요청하면 하루 동안 차단하게 했습니다.
  • 방화벽(firewalld)으로 꼭 필요한 포트만 외부에 열고, DB는 서버 안에서만 접속되게 했습니다.
  • GitHub Actions 배포용 SSH 키는 쓸 수 있는 명령을 제한(restrict)했고, UptimeRobot으로 웹과 SSH를 외부에서 감시합니다.
  • 점검에서 나온 항목을 하나씩 고쳤습니다.
    • 서버에 남아 있던 개인키가 어디에도 등록되지 않은 옛 키인 것을 확인하고 삭제했습니다.
    • 배포 워크플로가 외부 액션을 @master로 가져오고 있어서, 작성자 저장소가 바뀌면 배포 코드도 바로 바뀌는 상태였습니다. 릴리스의 커밋 해시로 고정했습니다.
    • 업로드 이미지 조회가 파일 이름을 경로에 그대로 이어 붙이고 있어서, ../ 같은 이름으로 다른 파일을 읽을 여지가 있었습니다. 업로드 폴더 밖을 가리키면 막는 공통 검사를 만들고 테스트를 붙였습니다. 운영에서도 공격 요청이 막히는 것을 확인했습니다.
  • OS를 Ubuntu 20.04에서 24.04로 올리기 전에 전체 백업을 받았고, 업그레이드 뒤 부팅 순서가 꼬여 서비스가 죽는 문제(cloud-init과 firewalld 충돌)를 찾아 해결했습니다.
성능 관리
  • 게임 서버를 systemd 서비스로 상시 가동하고, 비정상 종료되면 자동으로 다시 켜지게 했습니다. 종료할 때는 월드를 저장할 시간을 줍니다.
  • 6시간마다 서버를 재시작하는 타이머를 만들되, 접속자가 한 명이라도 있으면 그 회차를 건너뛰게 해서 플레이 중에는 끊기지 않게 했습니다.
  • CPU 전력을 1분마다 기록해 접속 인원별 부하를 봤습니다(대기 약 2.9W, 2명 접속 약 5W). 서버 렉 경고와 틱 지연(MSPT)도 함께 추적합니다.
  • "게임이 끊긴다"는 문의에는 서버 부하, 메모리, 온도, 네트워크 지연을 차례로 확인해 서버 문제가 아님을 밝히고, 사용자 PC의 랜 속도(100Mbps로 잡힘)가 의심된다고 안내했습니다.
접속 관리
  • 허용 목록(whitelist)과 정품 인증을 켜서 등록된 사람만 들어오게 했습니다.
  • 로그인 실패 로그를 모아 원인을 "인증 서버 일시 장애", "클라이언트와 서버의 모드 불일치", "프록시 멈춤"으로 나눴습니다. 접속 멈춤의 원인이던 절전용 프록시는 걷어 내고 상시 가동으로 바꿨습니다.
  • 플레이 중에는 30분마다 백업을 남기고(최대 48개), 디스크 여유 공간이 일정 이하로 줄지 않게 했습니다.
리포트
매일 아침 7시에 서버 로그, 재시작 기록, 전력 기록을 자동으로 모아 하루 운영 리포트를 만듭니다. 접속 시간, 재시작, 렉 경고, 전력을 표로 정리하고, 채팅 원문과 접속 IP 같은 개인정보는 넣지 않습니다. 정리에는 Claude를 활용했습니다.
남긴 것
작업할 때마다 날짜별 작업 기록을 서버에 남겨, 어느 PC에서 작업하든 이어서 볼 수 있게 했습니다. 회사에서 운영 시스템을 볼 때처럼 "변경 전 백업, 변경 내용 기록, 적용 확인" 순서를 지키는 연습이 됐습니다.
